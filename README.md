# JSON 三方合并台

一个纯本地的 JSON 三方合并工具（React + TypeScript + Vite）。输入页提供两种模式：**三份文档模式**直接粘贴或导入**基线（Base）**、**当前分支（Ours）**、**目标分支（Theirs）**三份 JSON；**RFC 6902 补丁模式**粘贴一份基线 JSON 与两份 JSON Patch（当前分支 / 目标分支各一份），补丁应用成功后自动进入合并。输入页还提供**变更交叉分析**入口：基于 Base / Ours / Theirs 计算两侧相对基线的结构化变更，按 JSON Pointer 展示影响矩阵（识别同一路径冲突，以及祖先整体替换 / 删除与后代修改的交叉影响；对象内互不相干的改动标为可自动合并，数组按整体值处理），支持按影响类型筛选、点击路径定位三方值，并可从分析结果继续进入合并流程。随后按 JSON Pointer 递归执行三方合并，在树形视图中定位并解决冲突，最终导出合并 JSON 与相对基线的 RFC 6902 补丁；输出阶段可配置**受保护路径检查**（命中敏感路径的变更需逐项确认后才可下载），还可挂载一份 **JSON Schema（Draft 2020-12）**，使用 [Ajv](https://ajv.js.org/) 对合并结果做约束校验。

## 快速启动（Docker Compose，一条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8080**

停止：`docker compose down`

## 操作方法

1. **输入**：输入页顶部可切换两种模式（两种模式的输入各自保留，切换不丢失）：
   - **三份文档**：在三个面板中分别粘贴或点击「导入文件」选择 `.json` 文件；
   - **RFC 6902 补丁**：粘贴一份基线 JSON 与两份 JSON Patch（详见下文「RFC 6902 补丁模式」）。

   可点击「加载示例数据」快速体验（按当前模式加载对应示例）。点击「开始合并」直接进入合并；也可先点击「**变更交叉分析**」查看两侧相对基线的变更影响矩阵（详见下文「变更交叉分析」），再从分析结果进入合并。此前保存的**会话快照**也可在此页通过「导入会话快照」恢复（见下文）。
2. **解决冲突**：
   - 左侧合并树按 JSON Pointer 层级展示合并结果，冲突节点以红色标出，点击即可定位；
   - 右侧面板显示冲突的三方值（基线 / 当前 / 目标）与冲突原因，可选择「采用当前分支」「采用目标分支」，或填写自定义 JSON 值；
   - 冲突面板顶部提供**撤销 / 重做**（详见下文），快捷键为 **Ctrl/⌘+Z** 与 **Ctrl/⌘+Shift+Z**（亦可 Ctrl/⌘+Y 重做）；
   - 冲突处理页下方提供**批量决策规则**编辑区，可按路径模式一次性处理一批冲突（详见下文）；
   - 顶部进度条显示已解决数量，全部解决后「生成合并结果」按钮可用；
   - 底部「下载会话快照」可随时保存当前进度（三份源 JSON + 已选解决方案）。
3. **导出结果**：查看合并后的 JSON 与相对基线的 RFC 6902 JSON Patch，支持一键复制或下载为 `merged.json` / `patch.json`；两面板上方提供**受保护路径检查**（详见下文「受保护路径检查」），下方还提供可编辑的**补丁审计**面板（详见下文「补丁审计」），以及**决策溯源**视图（详见下文「决策溯源」）。
4. **受保护路径检查**：在输出页「合并结果 / 补丁」两面板上方逐行配置保护规则；命中决策溯源变更时需逐项确认，未全部确认前 `merged.json` / `patch.json` 下载按钮保持禁用（详见下文「受保护路径检查」）。
5. **决策溯源**：在输出页「补丁审计」下方的**决策溯源**面板中，按最终结果相对基线的变更路径逐项核对每项决策的来源（详见下文「决策溯源」）。
6. **（可选）Schema 约束校验**：在输出页顶部勾选「JSON Schema 约束校验」：
   - 粘贴或「导入文件」载入一份 **Draft 2020-12** Schema，点击「应用 Schema」即对合并结果执行校验（支持文档内 `$ref` 与 `format` 等标准关键字）；
   - 错误按 **JSON Pointer（instancePath）分组**展示，每条显示关键字（keyword）、消息（message）与参数（params，如 `missingProperty`、`allowedValues`）；
   - 点击错误前的 **JSON Pointer 路径**，可直接在左侧合并结果视图中滚动并高亮对应值；
   - Schema JSON 解析失败、或包含**无法解析的本地 `$ref`** 时会给出明确错误提示，且**不会覆盖上一次有效的 Schema**（仍按旧 Schema 校验）；
   - 可随时取消勾选关闭校验；**开启校验且存在错误时仍允许下载**，下载按钮旁会显示「⚠ N 个校验错误」警示。

## RFC 6902 补丁模式

输入页顶部切换到「RFC 6902 补丁」后，只需提供三份输入：

- **基线 (Base)**：一份完整的 JSON 文档；
- **当前分支补丁 (Ours Patch)**：从基线到当前分支的 JSON Patch（RFC 6902 操作数组）；
- **目标分支补丁 (Theirs Patch)**：从基线到目标分支的 JSON Patch。

**应用语义**：

- 两份补丁**分别应用到同一基线的两份独立副本**上（基线本身不被修改），每份补丁内的操作**按数组顺序逐个应用**；
- 支持全部六种操作：`add` / `remove` / `replace` / `move` / `copy` / `test`；指针转义（RFC 6901 的 `~0` / `~1`）、数组索引与 `-` 追加、根路径 `""` 等语义由成熟库 [fast-json-patch](https://github.com/Starcounter-Jack/JSON-Patch) 实现；
- **任一操作失败即阻止进入合并流程**：本次输入内容保持不变，并在失败一侧的面板下标明**失败侧（当前分支补丁 / 目标分支补丁）、操作序号（从 1 开始）与失败原因**（如 test 断言失败、路径不存在、数组索引越界等）；两侧补丁的错误会同时标出，修正后重新点击「开始合并」即可；
- 两份补丁全部应用成功后，以「基线 + 两个应用结果」进入与三份文档模式完全相同的三方合并流程（冲突解决、批量规则、撤销重做、快照、导出、Schema 校验均可用）。

访问地址与三份文档模式相同：**http://localhost:8080**（Docker Compose 一键启动，见上文「快速启动」）。

## 变更交叉分析

入口：输入页（第 1 步）底部操作区的「**变更交叉分析**」按钮，两种输入模式（三份文档 / RFC 6902 补丁）均可用。点击后先按当前模式校验 / 解析三份输入（补丁模式含两份补丁的按序应用；任一失败就地报错，不进入分析），随后进入**影响矩阵**视图（Docker Compose 一键启动后全程在浏览器访问 **http://localhost:8080** 操作）。

分析基于 Base / Ours / Theirs，**分别计算当前分支与目标分支相对基线的结构化变更**，再按 **JSON Pointer（RFC 6901，根为「（根）」）** 汇总为影响矩阵：

- **结构化遍历口径**：只要某一侧的值是对象就按键递归，因此对象内互不相干的键改动会展开为各自独立的路径；**数组始终按整体值处理**（不展开内部下标），标量同理。
- **影响类型**（每行一条变更路径，矩阵按路径排序，祖先排在后代之前）：
  - **仅当前分支 / 仅目标分支**：只有一侧改动、与另一侧互不相干——**可自动合并**；
  - **双方同改一致**：两侧在同一路径改成相同值（含双方都删除同一键）——**可自动合并**；
  - **同一路径冲突**：两侧在同一路径改成不同的值（含一侧删除、另一侧修改），需人工裁决；
  - **祖先×后代交叉**：一侧在祖先路径**整体删除**或**整体替换**（替换为数组 / 标量等非对象值；也含在基线不存在处放上非对象值），另一侧改动了其**后代路径**——祖先条目与受影响的后代条目标为同一组交叉影响（后代行带「↳ 后代」标记并注明对侧祖先路径与变更形态），**真正需要裁决的冲突节点位于祖先路径**；一侧把对象换成另一个对象仍按键递归（后代删除冲突在后代路径暴露），不计此类。
- **汇总与冲突节点**：顶部显示变更路径总数、**可自动合并条数**与去重后的**需裁决冲突节点数**（同一路径冲突 + 交叉影响的祖先节点）；该冲突节点集合与后续三方合并实际产生的冲突完全一致；有冲突时顶部列出冲突节点路径胶囊。
- **按影响类型筛选**：矩阵上方的类型按钮可多选过滤（再次点击取消，「全部」恢复），每个按钮实时显示该类型条目数，计数为 0 时禁用；另有「**仅看冲突**」开关只保留两类冲突。
- **点击路径定位三方值**：点击任意矩阵行（或冲突节点胶囊），下方展开该路径的**基线 / 当前分支 / 目标分支**三方值，单侧未改动标注「未改动」，被删除标注「（不存在，已删除）」，并在行内显示两侧各自的新增 / 删除 / 整体修改标记；交叉影响的后代条目还会注明受对侧哪条祖先变更影响。
- **继续进入合并**：底部「← 返回编辑输入」保留三份输入内容，可修改后重新分析；「**开始合并 →**」以当前三份文档进入与直接点击「开始合并」完全相同的三方合并流程（冲突解决、批量规则、撤销重做、快照、导出、Schema 校验均可用）。

## 受保护路径检查

入口：第 3 步「导出结果」页面，「合并结果 JSON / RFC 6902 补丁」两面板上方（Docker Compose 一键启动后全程在浏览器访问 **http://localhost:8080** 操作）。用于在导出前强制核对敏感路径的变更：

- **逐行配置规则**：每行一条 **RFC 6901 路径模式**，语法与批量决策规则一致——以 `/` 开头、遵循 `~0` / `~1` 转义，整段 `*` 匹配恰好一个路径段、整段 `**` 匹配零个或多个路径段（如 `/services/*/password`、`/legacy/**`）；空行忽略。修改后点击「应用规则」生效，「清空」移除全部规则。
- **以决策溯源的最终变更为输入**：命中检查针对最终结果相对基线的每一处变更（与「决策溯源」清单同源，含被删除的值），与冲突是否已解决、来源类别无关。
- **命中语义**（变更路径 P，规则模式 R）：
  - R 匹配 P 本身或 P 的任一**祖先**路径——子路径变更会命中受保护的父路径（如规则 `/a` 命中 `/a/b` 的修改）；
  - P 为**整体替换或删除**时，R 匹配 P 的任一**后代**路径——父路径整体替换 / 删除必然波及其下所有受保护的后代路径（如规则 `/a/b` 命中 `/a` 的整体替换或删除；父路径整体**新增**不触发，因基线中该子树本不存在）。
- **命中清单**：每条命中项列出**命中的规则（行号 + 模式）、变更路径、变更类型（新增 / 删除 / 修改）与来源**（仅当前分支 / 仅目标分支 / 双方同改 / 冲突解决）；同一变更路径命中多条规则时**按变更路径合并**为一条展示。
- **逐项确认**：每条命中项需单独勾选确认；**未全部确认时 `merged.json` 与 `patch.json` 的下载按钮禁用**（复制与其他下载不受影响），全部确认后自动恢复。
- **确认状态随结果重置**：点击「← 返回继续调整」修改决策并重新生成结果后，命中清单按最新决策重算，**此前的确认全部清空**需重新逐项确认；已应用的规则配置则保留，无需重填。
- **非法配置就地提示**：某一行不是合法模式（不以 `/` 开头、非法 `~` 转义等）时，点击「应用规则」会在面板内逐行报错并标红输入框，**不会更新有效规则**——命中检查与确认状态仍沿用上一份合法配置。

## 补丁审计

输出页在「合并结果 / RFC 6902 补丁」两面板下方提供可编辑的**补丁审计**面板，用于验证（或手工改写后验证）一份 JSON Patch 是否确实能从基线回放得到当前合并结果：

- 面板加载时自动填入本次生成的 `基线 → 合并结果` RFC 6902 补丁，可直接在文本框中任意修改（支持 `add` / `remove` / `replace` / `move` / `copy` / `test` 全部六种操作）。
- 点击「**审计补丁**」后：
  1. 先解析补丁文本（JSON 语法与操作结构校验）；
  2. 再把操作**按数组顺序逐个应用到基线的一份独立副本**上（基线与合并结果始终只读，不被修改）；
  3. 回放完成后把回放结果与**当前合并结果**逐值深度比对。
- **审计结论**（三选一，外加格式错误）：
  - **应用失败**：显示**失败操作序号（从 1 开始）**与原因（如 test 断言失败、路径不存在、数组索引越界等）；
  - **不一致**：回放完成但结果与当前合并结果不同，显示**首个差异的 JSON Pointer**、该处的**期望值（当前合并结果）**与**实际值（补丁回放结果）**；缺失的键 / 越界的数组元素以「（不存在）」表示；差异按键序 / 下标深度优先、确定性地报告首个；
  - **审计通过**：回放结果与当前合并结果完全一致；
  - 补丁文本本身非法（JSON 语法错误、非法操作等）时提示「格式非法」并给出操作序号与原因，不进行回放。
- **重置为自动补丁**：随时丢弃编辑内容、恢复自动生成的补丁并清除旧审计结论。
- **复制 / 下载**继续可用：复制当前编辑文本，或下载为 `audit-patch.json`（与上方只读的自动补丁面板互不影响）。
- 审计编辑**绝不会修改合并结果**：合并结果 JSON、Schema 校验结果与上方自动补丁面板在任何审计操作后保持不变；修改文本后旧审计结论立即失效，需重新点击「审计补丁」。

## 决策溯源

入口：完成冲突解决后进入第 3 步「导出结果」，滚动到「补丁审计」面板下方即可看到**决策溯源**视图（Docker Compose 一键启动后全程在浏览器访问 **http://localhost:8080** 操作）。该视图用于逐项核对最终结果相对基线的每一处变更来自哪一侧、是否经历冲突裁决：

- **变更清单**：按路径列出最终结果相对基线的**全部变更**（与上方 RFC 6902 补丁一一对应），顶部汇总总数及**新增 / 删除 / 修改**计数；**被删除的值也作为条目保留**（标注为「删除」），不会因为值不存在而消失。
- **来源分类**，每条变更归入下列之一并以色块徽标区分：
  - **仅当前分支**：只有当前分支（Ours）相对基线修改；
  - **仅目标分支**：只有目标分支（Theirs）相对基线修改；
  - **双方同改**：两侧改成相同值（含双方都删除同一键）；
  - **冲突解决（采用当前）/（采用目标）/（自定义）**：该路径曾是冲突，按最终实际选择归类；自定义值回退为基线值时该路径相对基线无变更，不再列出。
- **路径遵循 RFC 6901**（`~` 转义为 `~0`、`/` 转义为 `~1`，根节点显示为「（根）」）。**父节点被整体替换或整体删除时只在父路径记一条**，不再重复列出随父节点失效的子路径（例如整个对象换成另一个对象、数组整体替换、一方删除另一方修改后采用删除侧）；对象内部逐键的就地修改、只加键 / 只删键则仍展开到具体子路径。
- **点击任意路径**展开详情，四栏并排显示**基线 / 当前分支 / 目标分支 / 最终值**；某侧或最终值缺失（删除 / 从未存在）时明确标注「（不存在）」。
- **按来源筛选**：清单上方的类别按钮可多选过滤（再次点击取消，「全部」恢复）；每个按钮实时显示该类别条目数，计数为 0 的类别自动禁用。
- **下载 JSON 报告**：点击「下载决策溯源报告 decision-trace.json」得到一份独立 JSON，包含格式标识、生成时间、按来源与变更形态的汇总计数，以及每个条目的路径、来源、变更形态与四方值；四方值统一以 `{ "present": true, "value": ... }` / `{ "present": false }` 表示，缺失值在报告中同样明确标注。
- **随决策实时更新**：点击「← 返回继续调整」修改冲突选择后重新生成结果，溯源清单与报告会按**最新决策**重新生成；例如把冲突从「采用当前」改为「采用目标」，对应条目的来源徽标、最终值与报告汇总立即随之变化。

## 批量决策规则

冲突处理页（存在冲突时）下方提供「批量决策规则」编辑区，适合冲突数量多、且可以按路径归纳处理方式的场景：

- **每条规则**包含一个 **JSON Pointer 模式**与一个选择（**采用当前分支** / **采用目标分支**），可任意增删、用 ↑ / ↓ 调整顺序。
- **模式语法**：
  - 必须以 `/` 开头，各路径段遵循 **RFC 6901** 转义（`~` 写作 `~0`，`/` 写作 `~1`；`~` 后只能跟 `0` 或 `1`）；
  - `*` 匹配**恰好一个**完整路径段（不跨 `/`，也不匹配零段），如 `/services/*/name` 命中 `/services/api/name`，但不命中 `/services/api/v2/name`；
  - `**` 匹配**零个或多个**完整路径段，如 `/services/**` 命中 `/services/api/name`，`/a/**/b` 同时命中 `/a/b` 与 `/a/x/y/b`；`/**` 以零段方式命中根节点冲突；
  - 段内出现的 `*`（如键名 `a*`，模式写作 `/a*`）按普通字面量处理，只有整段恰为 `*` / `**` 时才是通配。
- **实时预览**：每条规则右侧显示命中冲突总数（及其中尚未选择的数量），下方展开命中的冲突路径，点击可直接定位；**同时命中多条规则**的冲突会单独列出并标注命中的规则序号。
- **应用语义**：
  - 规则**自上而下**匹配，每个冲突只取**首条命中**的规则；
  - 只处理**尚未选择**的冲突；已有手动选择、自定义值或**快照恢复**的选择一律**跳过、绝不覆盖**（应用结果会提示跳过数量）；
  - 批量应用写入的是普通选择，应用后仍可在冲突面板**逐项改选**；可修改规则后再次应用（对已选择项仍保持幂等、不覆盖）；
  - **一次批量应用整体记为一个历史事务**：撤销 / 重做时同步恢复该批次涉及的全部冲突（见下文）。
- **非法模式**（不以 `/` 开头、非法 `~` 转义等）在编辑区**就地报错**并标红对应行，同时禁用「应用规则」按钮，阻止本次应用。

## 决策撤销 / 重做

冲突处理页（右侧面板顶部）提供「↩ 撤销」「↪ 重做」按钮，悬停可查看将要撤销 / 重做的具体操作：

- **事务粒度**：
  - 每次手动「采用当前分支」「采用目标分支」或提交「自定义值」记为**一个历史事务**；
  - **一次批量规则应用**（即使涉及多个冲突）整体记为**一个事务**，撤销或重做时会**同步恢复该批次涉及的全部冲突**，批次外的已有选择不受影响。
- **重做分支**：撤销后若做出新的决策（含再次应用批量规则），会清空当前重做分支；提交与现状完全相同的选择不产生事务（例如对已选侧再次点击同一按钮）。
- **按钮状态**：没有可撤销 / 可重做记录时，对应按钮自动禁用。
- **快捷键**：`Ctrl/⌘+Z` 撤销，`Ctrl/⌘+Shift+Z`（或 `Ctrl/⌘+Y`）重做。焦点位于**文本输入框 / 自定义值文本域**等编辑控件内时**不会拦截**，仍使用浏览器原生的编辑撤销 / 重做。
- **初始状态不可撤销**：通过**会话快照恢复**出的选择作为不可撤销的初始状态（历史栈为空）；随后新做的决策照常记录。
- **跨阶段保留**：进入输出页后点击「← 返回继续调整」回到冲突处理页时，完整的撤销 / 重做历史仍可继续使用；点击「重新开始」或重新执行一次合并才会清空。

## 会话快照（中断后继续）

- **下载快照**：在冲突处理页底部点击「下载会话快照」，得到 `merge-session-snapshot.json`，内容包含格式版本、三份源 JSON（base / ours / theirs）与当前已选择的解决方案。
- **导入快照**：在输入页点击「导入会话快照」选择之前下载的快照文件：
  - 导入时用快照中的三份源 JSON **重新执行三方合并**，再恢复选择；
  - 仅当某个冲突的 **JSON Pointer 及 base / ours / theirs 三方值**与快照记录完全一致时才恢复该项选择（**绝不按旧冲突序号套用**）；
  - 不满足条件的条目会被跳过，并在合并页顶部汇总显示每项的跳过原因；
  - 快照结构或字段非法时给出明确错误提示，且**不影响当前会话**（输入内容保持不变）；
  - 导入成功后显示恢复 / 跳过数量，并自动定位到首个未解决冲突。

### 快照格式

```json
{
  "format": "json-three-way-merge/session",
  "version": 1,
  "base": { "..." : "基线文档" },
  "ours": { "..." : "当前分支文档" },
  "theirs": { "..." : "目标分支文档" },
  "resolutions": [
    {
      "pointer": "/features/logging",
      "base": { "present": true, "value": "info" },
      "ours": { "present": false },
      "theirs": { "present": true, "value": "warn" },
      "resolution": { "kind": "theirs" }
    }
  ]
}
```

- `format` / `version`：格式标识与版本（当前为 `1`），不匹配时拒绝导入。
- `base` / `ours` / `theirs`：三份源 JSON 文档（完整内容）。
- `resolutions[]`：已选择的解决方案。每项以 `pointer`（RFC 6901 JSON Pointer，根为 `""`）定位冲突，并记录冲突的 base / ours / theirs 三方值用于导入时校验；某侧 `present` 为 `false` 表示该侧此节点不存在（已删除），为 `true` 时必须带 `value`。
- `resolution.kind`：`ours`（采用当前分支）/ `theirs`（采用目标分支）/ `custom`（自定义值，需带 `value` 字段）。

## 合并规则

按 JSON Pointer 逐节点递归比较三方：

| 情况 | 结果 |
| --- | --- |
| 仅一侧相对基线变化 | 采用变化的一侧 |
| 双方改成相同的值（含都删除） | 采用一次 |
| 双方改成不同的值 | **冲突** |
| 一侧删除、另一侧修改 | **冲突** |

- 只有**对象**会按键递归合并；**数组和标量均按单个值整体处理**（双方改同一数组即冲突）。
- 双方新增的对象会按键递归合并；一方删除、另一方修改对象时整体记为冲突。
- 冲突解决方式：采用当前分支 / 采用目标分支 / 自定义 JSON 值（可表示删除以外的任意值）；也可在冲突处理页通过**批量决策规则**按路径模式（`*` / `**` 段通配）一次性处理多个未选择的冲突。

## 输出说明

- **合并结果 JSON**：应用所有自动合并与冲突解决后的完整文档（带行号显示，便于按 JSON Pointer 定位）。
- **RFC 6902 补丁**：`基线 → 合并结果` 的 JSON Patch（`add` / `remove` / `replace`），路径按 RFC 6901 转义（`~` → `~0`，`/` → `~1`）。
- **受保护路径检查**：逐行配置 RFC 6901 路径模式（`*` / `**` 段通配），以决策溯源的最终变更为输入计算命中；子路径变更命中受保护父路径、父路径整体替换 / 删除命中任一后代规则；命中项按变更路径合并展示（规则 / 路径 / 类型 / 来源）并需逐项确认，未全部确认时禁用 `merged.json` / `patch.json` 下载；非法配置就地报错且不更新有效规则，返回调整重新生成后确认清空、规则保留（详见上文「受保护路径检查」）。
- **补丁审计**：可编辑面板，把修改后的补丁按序在基线独立副本上回放并与合并结果比对；报告从 1 开始的失败操作序号与原因，或首个差异 JSON Pointer + 期望值 / 实际值，一致时显示通过；可重置为自动补丁，编辑不影响合并结果（详见上文「补丁审计」）。
- **决策溯源**：最终结果相对基线的变更路径清单，逐项归类为仅当前分支 / 仅目标分支 / 双方同改 / 冲突解决（采用当前、目标或自定义），删除值也保留为条目；点击路径查看基线、两侧与最终值（缺失标注「（不存在）」），支持按来源筛选并下载 `decision-trace.json` 报告；返回调整后重新生成即反映最新决策（详见上文「决策溯源」）。
- **Schema 校验**：可选的 Draft 2020-12 约束校验（Ajv，`allErrors` 模式），错误按 instancePath 分组，不阻断下载，仅在下载旁给出错误数警示。
